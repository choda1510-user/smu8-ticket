
# APIs Coding Rules

이 디렉토리는 API 호출 함수를 관리하는 공간입니다.

외부 통신시 반복되는 url, 쿼리 파라미터, 헤더, 본문 작성, 응답 파싱 등을 분리합니다.

## 1. 파일 이름 규칙

API 파일은 반드시 `Api.ts`로 시작하고 camelCase를 사용합니다.

## 2. 함수 이름 규칙

API 함수 이름은 기능을 잘 설명하는 이름으로 짓습니다.

API 함수들은 export default로 내보내지 않고 각자 따로 export 합니다.

## 3. API 내부 책임 범위

API 파일은 하나의 도메인을 범위로 갖습니다.

API 함수는 하나의 기능을 범위로 갖습니다.

## 4. Hook 로직, 컴포넌트 로직과 분리

API 함수에는 Hook을 사용하지 않습니다.

상태와 동작은 `@/src/hooks` 디렉토리에서 처리하고, API은 외부 시스템과의 통신만 담당합니다.

## 5. 매개 변수 규칙

API 함수의 props가 복잡하면 `@/src/types`의 타입을 사용합니다.

적절한 타입이 없다면 작업을 중단하고 문제 원인을 알립니다.

API 함수는 브라우저 이벤트를 매개변수로 받지 않습니다.

## 6. 반환값 규칙

반환은 `@/src/types`에 정의된 타입으로 반환하거나, 정의된 타입을 제네릭 타입으로 하는 Promise 타입으로 반환합니다.

적절한 타입이 없다면 작업을 중단하고 문제 원인을 알립니다.

## 7. 디렉토리 구조

API이 많아지면 도메인별로 분리합니다.

공통 API은 `@/src/apis` 루트에 둡니다.

특정 도메인에서만 사용하는 API은 해당 도메인 하위 디렉토리에 둡니다.

## 8. PR 체크리스트

API을 추가하거나 수정할 때는 다음을 확인합니다.

* API 파일 이름이 `Apis.ts`로 끝나는가?
* API 함수가 하나의 책임만 가지는가?
* API 함수가 Hook을 사용하지 않는가?
* JSX를 반환하지 않는가?
* 반환값의 의미가 명확한가?
* TypeScript 타입이 `@/src/types`안에 존재하는 타입인가?
* 컴포넌트와 훅에서 중복되던 로직이 API으로 적절히 분리되었는가?
