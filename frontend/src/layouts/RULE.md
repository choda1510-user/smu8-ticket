# layouts 작업 규칙

## 역할
- `layouts` 폴더는 라우트별 공통 화면 뼈대를 담당한다.
- `Outlet`을 기준으로 공통 UI와 페이지 본문 영역을 배치한다.
- 헤더, 사이드바, 검색 결과 메뉴 같은 공통 조각은 `sections`에서 가져와 조합한다.
- 실제 페이지 콘텐츠는 `pages`에서 렌더링한다.

## 구조
- 모든 layout 컴포넌트는 `Outlet`을 포함해야 한다.
- layout은 페이지 데이터를 직접 가져오지 않는다.
- layout은 라우팅 구조와 공통 배치만 담당한다.
- 중첩 라우트 구조는 `App.tsx`와 일치해야 한다.

## 데이터와 상태
- layout에서 fetch, API 호출, JSON 로딩을 하지 않는다.
- layout 내부 상태는 접힘/펼침, 메뉴 표시 여부 같은 레이아웃 UI 상태로 제한한다.
- 페이지별 선택값이나 상세 데이터는 `pages` 또는 `hooks`에서 처리한다.

## 스타일
- layout별 CSS 파일이 있는 경우 기존 `LayoutName.css` 패턴을 유지한다.
- 전체 폭, 본문 정렬, 사이드 영역 배치처럼 화면 골격에 해당하는 스타일만 layout CSS에 둔다.
- 버튼, 카드, 리스트 같은 페이지 내부 UI 스타일은 `pages` 또는 `sections`에서 관리한다.

## 금지
- layout에 페이지 전용 UI를 직접 구현하지 않기
- layout에서 API URL 또는 JSON 파일 경로를 직접 작성하지 않기
- layout에서 특정 페이지의 상세 데이터를 props 없이 하드코딩하지 않기
- `Outlet` 없이 단독 페이지처럼 작성하지 않기
