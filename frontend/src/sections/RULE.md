# sections 작업 규칙

## 역할
- `sections` 폴더는 여러 페이지나 레이아웃에서 재사용되는 화면 조각을 담당한다.
- 헤더, 사이드바, 검색 결과 탭, 페이지네이션처럼 페이지보다 작은 공통 UI를 둔다.
- 전체 페이지 레이아웃을 감싸는 구조는 `layouts`에 둔다.
- 특정 페이지에서만 쓰는 작은 UI는 우선 해당 페이지 파일 안에 둔다.

## 데이터와 상태
- `sections`는 가능한 한 props 또는 URL 상태를 받아 렌더링한다.
- 임시 더미 데이터나 고정 검색어를 컴포넌트 내부에 직접 선언하지 않는다.
- 서버 데이터 조회, JSON fetch, API 호출은 `sections`에서 직접 처리하지 않는다.
- 검색어, 현재 페이지, 선택 탭처럼 UI 동작에 필요한 최소 상태만 가질 수 있다.


## 스타일
- 섹션별 CSS 파일이 이미 있는 경우 기존 `ComponentName.css` 패턴을 유지한다.
- className 기반 스타일을 우선 사용한다.
- 기존 클래스 이름과 레이아웃 구조를 불필요하게 바꾸지 않는다.

## 금지
- 페이지 전체 구조를 `sections`에 구현하지 않기
- 페이지별 비즈니스 로직을 `sections`에 넣지 않기
- API URL 또는 JSON 파일 경로를 `sections`에 직접 작성하지 않기
- 같은 헤더, 사이드바, 페이지네이션 UI를 페이지마다 중복 구현하지 않기
