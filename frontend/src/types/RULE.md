## 역할

이 디렉토리는 프로젝트에서 여러 파일이 함께 사용하는 TypeScript 타입을 정의하는 곳입니다.

페이지, 훅, 컴포넌트 여러 곳에서 반복해서 사용하는 데이터 모양은 이곳에 타입으로 분리합니다.

## 기본 원칙

- TypeScript 타입은 실제 데이터 구조를 기준으로 작성합니다.
- 백엔드 API 응답, JSON 목업 데이터, 공통 props처럼 여러 곳에서 재사용되는 타입을 우선적으로 정의합니다.
- 한 파일에서만 사용하는 작은 타입은 해당 파일 내부에 둘 수 있습니다.
- 두 곳 이상에서 같은 타입이 필요해지면 `src/types`로 분리합니다.
- `any` 타입은 사용하지 않습니다.
- 타입을 모를 때도 가능한 범위를 좁혀서 작성합니다.

## 타입 선언 방식

- 객체 데이터의 모양은 `type`으로 정의하는 것을 기본으로 합니다.
- React 컴포넌트 props는 최상위 `AGENTS.md` 규칙에 따라 `interface` 사용을 우선합니다.
- 공통 API 응답처럼 제네릭이 필요한 타입은 `type`으로 정의합니다.


## 파일 작성 규칙

- 타입 파일은 역할이 드러나는 이름으로 작성합니다.
    - `api.ts`
    - `booking.ts`
    - `concert.ts`
    - `member.ts`
- 공통 API 응답 타입은 `api.ts`에 둡니다.
- 도메인별 타입은 도메인 이름을 가진 파일에 둡니다.
    - 예매 관련 타입: `booking.ts`
    - 공연 관련 타입: `concert.ts`
    - 회원 관련 타입: `member.ts`
- 하나의 파일에 서로 관련 없는 타입을 과도하게 모으지 않습니다.

## 이름 규칙

- 타입 이름은 PascalCase를 사용합니다.
    - `BookingItem`
    - `BookingDetail`
    - `ConcertDetail`
    - `ListResponse`
- 배열 안의 단일 항목 타입은 `Item` 또는 도메인 이름을 사용합니다.
    - `BookingItem`
    - `ConcertItem`
- 상세 데이터 타입은 `Detail`을 사용합니다.
    - `BookingDetail`
    - `ConcertDetail`
- API 응답 전체를 표현하는 타입은 `Response`를 붙입니다.
    - `ListResponse<T>`
    - `BookingListResponse`

## export 규칙

- 다른 파일에서 사용할 타입은 반드시 `export`합니다.
- 해당 파일 내부에서만 사용하는 보조 타입은 export하지 않습니다.
- 타입을 import할 때는 가능하면 `import type`을 사용합니다.


## 선택 속성 규칙

- 데이터에 항상 존재하지 않을 수 있는 값은 `?`를 붙입니다.


- 값이 없을 수 있다는 의미가 명확한 경우에만 `null`을 사용합니다.
- 단순히 아직 데이터가 로딩되지 않은 상태는 타입에 `null`을 섞기보다 초기값을 사용합니다.

## 목업 데이터와 타입

- `src/data`의 JSON 구조와 타입 구조는 서로 맞아야 합니다.
- JSON에 있는 필드는 타입에도 있어야 합니다.
- 타입에 필수로 정의한 필드는 JSON에도 있어야 합니다.
- 백엔드 API가 연결되면 기존 JSON 타입을 기준으로 API 응답 타입을 정리합니다.

## 금지 사항

- `any`로 타입 오류를 임시로 덮지 않습니다.
- 같은 데이터 모양을 여러 파일에서 중복 선언하지 않습니다.
- 실제로 사용하지 않는 타입을 미리 많이 만들지 않습니다.
- 백엔드 응답 구조와 다른 타입 이름이나 필드명을 임의로 만들지 않습니다.
- 타입 파일 안에 화면 로직, fetch 로직, React 컴포넌트를 작성하지 않습니다.
