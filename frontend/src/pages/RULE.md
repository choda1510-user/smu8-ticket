# pages 작업 규칙

## 역할
- `pages` 폴더의 파일은 화면 렌더링과 사용자 이벤트 연결만 담당한다.
- 데이터 조회, API 호출, JSON 로딩 로직은 페이지 파일에 작성하지 않는다.
- 페이지는 필요한 데이터를 커스텀 훅에서 받아 사용한다.

## 데이터 사용
- 페이지 내부에 배열/객체 형태의 더미 데이터를 직접 선언하지 않는다.
- 목록 데이터는 커스텀 훅에서 받은 응답의 `data` 값을 렌더링에 사용한다.
- 페이지에서는 데이터를 새로 불러오지 않고, 화면 표시에 필요한 최소 가공만 한다.

## 네비게이션
- 라우팅 이동은 `useNavigate`를 사용한다.
- URL 경로는 `App.tsx`에 정의된 라우트 구조를 따른다.
- 상세 페이지 이동 경로는 기존 패턴을 유지한다.
  - 공연 상세: `/concerts/:concertId`
  - 예매 상세: `/mypage/reserve/:reserveId`
  - 검색 결과: `/search/all`, `/search/concerts`, `/search/venues`

## 컴포넌트 작성
- 페이지 파일은 기본 export로 페이지 컴포넌트를 내보낸다.
- 페이지 내부에서만 사용하는 작은 UI 컴포넌트는 같은 파일 하단에 둘 수 있다.
- 여러 페이지에서 재사용될 UI는 `sections` 또는 `component` 폴더로 분리한다.

## 스타일
- 기존 페이지의 `const styles: Record<string, CSSProperties>` 패턴을 유지한다.
- 전역 스타일이 필요한 경우가 아니면 페이지 전용 CSS 파일을 새로 만들지 않는다.
- 기존 페이지 폭과 레이아웃 흐름을 우선 유지한다.

## 금지
- 페이지 파일에 `fetch()` 직접 작성 금지
- 페이지 파일에 API URL 직접 작성 금지
- 페이지 파일에 JSON 더미 데이터 직접 선언 금지
- 레이아웃, 헤더, 사이드바, 검색 탭 같은 공통 UI를 페이지 안에 중복 구현하지 않기
