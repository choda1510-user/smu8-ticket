## 역할

이 디렉토리는 프론트엔드 화면 개발에 사용하는 목업 JSON 데이터를 관리합니다.

실제 API 연동 전 화면 표시와 훅 동작을 확인하기 위한 데이터만 둡니다.

## 파일 규칙

- 데이터 파일은 `.json` 확장자를 사용합니다.
- 파일명은 데이터가 사용되는 화면이나 도메인이 드러나도록 camelCase로 작성합니다.
    - `concertDetail.json`
    - `bookingList.json`
    - `globalConcertResults.json`
- React 컴포넌트, 훅, CSS 파일은 이 디렉토리에 작성하지 않습니다.
- 데이터와 직접 관련 없는 문서나 설정 파일은 추가하지 않습니다.

## JSON 작성 규칙

- JSON은 유효한 문법으로 작성합니다.
- 들여쓰기는 공백 2칸을 사용합니다.
- 키 이름은 기존 데이터와 동일하게 camelCase를 사용합니다.
- 같은 목록 안의 객체는 동일한 필드 구조를 유지합니다.
- 페이지네이션이 필요한 목록 데이터는 기존 형식처럼 `data`, `page`, `totalPage` 구조를 우선합니다.
- 단순 목록 데이터는 기존 형식처럼 배열 루트 구조를 사용할 수 있습니다.
- 상세 데이터는 기존 형식처럼 객체 루트 구조를 사용할 수 있습니다.

## 데이터 값 규칙

- 목업 값은 화면에서 의미를 확인할 수 있는 한국어 문자열을 사용합니다.
    - `공연명`
    - `공연기간`
    - `공연장명`
    - `예매상태`
- id 값은 숫자로 작성합니다.
- 서로 연결되는 데이터의 id 값은 일관되게 유지합니다.
    - `concertId`
    - `venueId`
    - `reserveId`
- 상태 값은 화면에서 사용하는 표현과 맞춥니다.
    - `예매중`
    - `예매예정`
- 불필요하게 실제 개인정보, 실제 예매번호, 민감한 값을 넣지 않습니다.

## 타입 연동 규칙

- JSON 구조를 변경할 때는 해당 데이터를 읽는 훅과 `src/types`의 타입 정의를 함께 확인합니다.
- 기존 화면에서 사용하는 필드는 설명 없이 삭제하거나 이름을 변경하지 않습니다.
- 새 필드를 추가할 때는 사용하는 화면 또는 훅에서 실제로 필요한 값인지 확인합니다.
- API 응답을 가정한 데이터는 가능한 한 실제 응답 구조와 비슷하게 유지합니다.

## 금지 사항

- 요청 없이 모든 목업 데이터를 실제 데이터처럼 대량 교체하지 않습니다.
- 요청과 관련 없는 JSON 파일의 구조를 변경하지 않습니다.
- 화면에서 사용 중인 키 이름을 임의로 바꾸지 않습니다.
- 검증되지 않은 외부 데이터나 민감 정보를 추가하지 않습니다.
